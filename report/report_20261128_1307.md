# Звіт: P6a — сповіщення в застосунку і пуші

## Завдання (дослівно від хаба)

Беру P6 (сповіщення; разом із `tasks/commandvibe/2026-11-28-push-notifications.md`): напиши план і виконуй. Для P6 — урок із medvibe: на iOS пуші не працювали ніколи, бо в `Runner.entitlements` не було `aps-environment` (без нього iOS не видає APNs-токен і не дає помилки). Додай його в план одразу, плюс `registerForRemoteNotifications`; у список кроків власника: APNs-ключ (.p8) у Firebase `commandvibe-ks` для iOS-застосунку, VAPID-ключ для вебу. Перевірка «токен → `PUT /me/push-token` → пуш дійшов» — у ручному списку кінця хвилі. Рішення 1–6 (поза дизайном) погоджено; працювати без власника; пристрої — Samsung R5CX706X9WL, iOS — у кінці хвилі. Застосунок звертається до `PushService` через тонкий шар (можливий перехід на пакет `ks_push`).

Модель сеансу: Sonnet 5.5.

## Що зроблено

План: `docs/superpowers/plans/2026-11-28-wave1-p6a-notifications.md` (11 задач). Telegram-бот і Mini App — P6b (потрібен токен бота від власника).

**Сервер**
- Модуль `shared/push` (копія з ks_server v0.4.0, `sync:push`/`sync:push:check` у `check.sh`), `PUT|DELETE /me/push-token`; акаунти `o:<uid>` / `m:<memberId>`.
- `NotificationRepository` (пам'ять + Firestore, контракт), `NotificationsService`, `GET /groups/:id/notifications`, `POST …/read`, події `notification.created|read`.
- Джерела: день відкрито, розкриття, черга, коментар (+`by` у події), лайки (один запис, лічильник росте), новий учасник на підтвердженні, скарга; вилучення учасника чистить його записи.
- `PushNotifier`: категорії, тихі години 22–08 (з урахуванням DST), ліміт 3 неособистих на добу, тексти без імен; налаштування `GET|PUT /groups/:id/me/notification-settings`.
- Вечірнє нагадування в `/internal/tick` (19:00–22:00 за часом групи, раз на день, лише тим, хто не виконав).

**Застосунок**
- `ks_core` v0.8.0; шар `core/push/*` (`push_gateway.dart` — єдине місце, що називає бібліотеку), `AppPush`, `SessionHttpClient`, видалення токена перед вибраним виходом.
- Платформа: `aps-environment`, `UIBackgroundModes`, `registerForRemoteNotifications`, `POST_NOTIFICATIONS`, core library desugaring (вимагає `flutter_local_notifications`), `firebase-messaging-sw.js`; тест на файли.
- Дзвіночок у `TabPage`, екран `/g/:id/notifications`, спливні повідомлення, крапки на вкладках, відкриття з пуша (лише `/g/<id>/<сторінка>`), картка налаштувань і дозволу.

## Перевірки

- Сервер: `./scripts/check.sh` — unit 896, e2e 146, lint, typecheck, build, sync — зелені.
- Застосунок: `flutter analyze --fatal-infos` чисто, 416 тестів; збірки web, Android (debug APK), iOS (simulator build) зелені.
- Браузерний e2e `tool/e2e_web.mjs` — проходить, включно з дзвіночком (лайк Bella → запис у Webby → тап → стрічка) і карткою налаштувань.
- Контракт Firestore (емулятор у Docker, `--runInBand`): усі тести сповіщень проходять; падають 1–2 старі тести паралельності (`names unique under concurrency`, `submissions.put` ×10) через 5-секундний таймаут під емуляцією Docker — не пов'язані з P6a (треба окремо глянути).

## Синхронізація

Запити клієнта: `PUT /me/push-token {token, platform}` після входу, при оновленні токена й після дозволу; `DELETE /me/push-token {token}` перед вибраним виходом; `GET /groups/:id/notifications`, `POST …/read {ids?}`; `GET|PUT /groups/:id/me/notification-settings`. Живі події: `notification.created|read` `{recipients}`.

## Кроки власника (в консолях)

APNs `.p8` у Firebase `commandvibe-ks` для iOS-застосунку; Push Notifications в App ID `com.karavanstudio.commandvibe`; VAPID-ключ (`--dart-define=VAPID_KEY`); FCM API v1 і право сервісного акаунта Cloud Run; пізніше токен Telegram-бота (P6b). Деталі — `docs/deploy.md`.

## Ручна перевірка (кінець хвилі)

Токен → `PUT /me/push-token` → пуш дійшов на закритому застосунку → тап відкриває потрібну вкладку (Samsung, потім iOS, веб).
