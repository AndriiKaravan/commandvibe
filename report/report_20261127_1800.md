# Звіт 2026-11-27 18:00 — перехід на модуль `auth` з ks_core 0.7.0

## Завдання
Хаб: «CommandVibe: перехід на модуль `auth` з ks_core 0.7.0 (веб + Android + iOS)» (`tasks/commandvibe/2026-11-27-ks-core-auth-0-7-0.md`): тег v0.7.0, свій код входу — на `AuthService`/`FirebaseAuthService`, `AuthHttpClient` з `authorizeHosts` лише для API, прямі `firebase_auth`/`firebase_core` — на діапазони бібліотеки, перевірка на реальних пристроях пунктів 5–7 рев'ю ks_core, веб-деплой лише з «так» власника. Окремо від хабу: виправити або пояснити нестабільний контракт-тест конкурентних імен.

## Що зроблено
- `ks_core` → `v0.7.0`; прямий `firebase_auth` прибрано (не імпортується), `firebase_core` лишився в діапазоні бібліотеки.
- `KsOrganizerSignIn` (`app/lib/core/platform/ks_organizer_sign_in.dart`): `OrganizerSignIn` поверх `AuthService`; скасування → `SignInCancelled`, відмова → `OrganizerSignInFailed(reason)`, веб-redirect → `null`. Старі `organizer_sign_in_io/web.dart` видалено. 8 юніт-тестів з `FakeAuthService`.
- Google: Android — рідний вибір акаунта (`serverClientId` = веб-клієнт проєкту), iOS — `clientId` iOS-клієнта і URL-схема `REVERSED_CLIENT_ID` у `Info.plist`, веб — popup з переходом на redirect (authDomain = домен сторінки, як було).
- iOS: `pod update GTMSessionFetcher` (старий пін 5.3.1 конфліктував з GoogleSignIn 9).
- `AuthHttpClient`/`authorizeHosts` не застосовано: клієнт отримує Firebase-токен лише щоб обміняти його на власну сесію API; мережевий клієнт далі `ApiClient` з токенами сесії.
- Нестабільний тест `names unique per group under concurrency`: у 25 ізольованих запусках на емуляторі не відтворився (падав 1 з 3 повних прогонів). Причина не доведена; прибрано очевидну діру — `ALREADY_EXISTS` (gRPC 6) при `tx.create` тепер дає `NameTakenError` (окремий коміт).

## Чекає пристроїв власника (реальні, без симуляторів)
1. Android: чи відкривається рідний вибір Google і чи приймає сервер токен. **Ризик:** у `apps:sdkconfig` Android-застосунку немає OAuth-клієнта типу 1 (Android + SHA-1); без нього модуль дасть `misconfigured`. Потрібно додати SHA-1 (debug і release/Play) у Firebase Console → Project settings → Android app (консоль — лише власник).
2. iOS: вхід через рідний вибір; URL-схема в `Info.plist` додана.
3. Веб: popup і redirect у вбудованих браузерах (Instagram/Telegram/Viber).
4. П. 5–7 рев'ю ks_core: вхід за посиланням при анонімі й існуючому акаунті; `intent://` «відкрити в браузері» — у CommandVibe поки не використовуються (вхід лише Google), тож перевірка можлива тільки після додавання відповідного UI; знахідки — хабу як задача для ks_core.
5. Веб на живий сайт — після «так» власника.
