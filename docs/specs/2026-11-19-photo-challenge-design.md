# Групова фото-челендж гра — дизайн

**Дата:** 2026-11-19, оновлено 2026-11-20 (вичитка власника, розділи 1–5) · **Статус:** погоджено власником 26.11 (вичитано повністю; уточнення — розділ 2а) · **Назва:** CommandVibe (рішення власника 26.11, розділ 15а)
**Джерело:** `SPEC.md` власника (листопад 2026) + рішення власника 19–20.11.

Документ містить лише узгоджене і те, що ще обговорюємо (позначено «пропозиція хабу» або посиланням на питання в розділі 15).

---

## 1. Що робимо і навіщо

Ігрова кімната для закритої групи (колеги, студенти, друзі, сім'я). Організатор запускає гру на кілька тижнів і обирає завдання з бази. Щодня відкривається нове завдання, учасники підтверджують виконання фото. Чужі фото розмиті: виконай завдання — і побачиш одразу, або чекай 2 дні. Бали, рейтинг, наприкінці переможці й спільний колаж.

**Навіщо зараз:** новорічний сезон — найсильніший вхід («адвент-челендж»). Перший запуск дає відгуки, фото й кейси для продажів B2B навесні й наступного грудня.

**Успіх першого сезону:** 3–5 знайомих груп дограли до фіналу, більшість учасників виконала понад половину завдань, є колажі, HR-звіт і відгуки, які можна показати.

## 2а. Уточнення власника 26.11 (мають пріоритет над текстом нижче)

Вікно CommandVibe знайшло суперечності; рішення:
1. **Старт перших груп — 8–12 грудня** (не «до 01.12» і не «3–7 грудня»).
2. **Розкриття фото — 9:00 за часом групи скрізь.**
3. **Рулетка — у хвилі 1** (на екрані «Сьогодні»), разом з «авто щодня».
4. **Таємний Санта — не пріоритет**: поза першим сезоном.
5. **«Підтверджувати нових» — вимкнено за замовчуванням** (вхід за 10 секунд); організатор вмикає сам.
6. **Firebase на клієнті — як у duval і medvibe:** клієнт використовує Firebase Auth (і App Check) через спільні бібліотеки, усі дані — лише через сервер. Усе, що вже є в спільних бібліотеках (ks_core: мережа, realtime, логування, телеметрія, оновлення, туторіали, інтегрити; ks_server: realtime-шлюз), — береться звідти; чого бракує і що потрібне ще комусь — **виносимо в бібліотеку** окремою задачею бібліотеки (зміна бібліотеки — з явного «так» власника на конкретну задачу).
7. **Бібліотеки готові:** ks_server v0.3.0, ks_core v0.6.2 (з realtime). Чи працює realtime і камера у Flutter Web (iPhone Safari, Samsung) — **перевірка першого дня**.
8. Дизайн **погоджено власником**.

## 3. Цілі, не-цілі, анти-цілі

**Цілі**
- Учасник входить у гру за посиланням за 10 секунд, без пошти, телефону й встановлення застосунку.
- Організатор після налаштування нічого не веде вручну.
- Чуже фото неможливо побачити раніше, ніж дозволяють правила, — навіть технічно підкованому учаснику.
- Учасник завжди розуміє, чому фото розмите і що зробити, щоб його побачити.
- Фото й дані групи зникають за розкладом; учасник може видалити свої будь-коли.
- HR-звіти для організатора: агреговані, без стеження за людьми (SPEC §11).
- Англійська версія гри, сторінки й бази завдань.
- Гру знаходять у пошуку: публічна сторінка на karavanstudio.dev.

**Не-цілі першого сезону:** оплата, стори, Slack/Teams, SSO, AI-перевірка фото.

**Анти-цілі** (провал, навіть якщо все працює)
- Гра стає інструментом стеження за працівниками.
- Фото витікають за межі групи або лишаються після обіцяного видалення.
- Організатору доводиться щодня щось робити руками, щоб гра йшла.

## 4. Підхід

**Flutter Web (PWA) + Node-сервіс із REST і WebSocket.** Клієнт працює лише з сервісом; сервіс — з Firestore і Storage через репозиторії. Telegram — додатковий канал: бот для сповіщень (хвиля 1) і Mini App як другий спосіб входу (хвиля 2).

Чому так (рішення власника 20.11): переїзд бази непомітний для користувачів; уся ігрова логіка й увесь захист фото в одному місці. Ціна: WebSocket, перепідключення й кеш — більше роботи, ніж читання напряму з Firestore.

## 5. Архітектура

```
Пошук / прев'ю посилань ──> karavanstudio.dev/<гра> (статичний HTML, sitelanding)
                                    │ «Увійти» / посилання-запрошення
                                    ▼
Flutter Web (PWA) ──REST──> Node-сервіс (Cloud Run) ──> Firestore / Storage (Admin SDK)
       ▲  ◀──WebSocket──┘          │   (клієнт до бази й сховища доступу не має)
       └── фото: короткі підписані посилання від сервісу
Cloud Scheduler ──кожні 5 хв──> сервіс: відкрити завдання, розкрити фото, нагадати, видалити
Telegram ⇄ сервіс (webhook бота; Mini App — хвиля 2)
```

### 5.1 Застосунок і сервіс
- **Окремий Firebase-проєкт**, регіон ЄС (Firestore і Storage — `europe-west`; Cloud Run — `europe-central2`, як duval_backend).
- **Клієнт:** Flutter Web, PWA, Firebase Hosting. go_router, ChangeNotifier/MVVM (глобальні правила власника). Звертається лише до сервісу: REST для дій і читання, WebSocket для живих оновлень. Дані — через шар репозиторіїв.
- **Сервіс:** Node.js + TypeScript на NestJS, як medvibe_backend і duval_backend. Уся ігрова логіка, усі перевірки доступу, видача фото. Секрети — лише Secret Manager. Деплой: ревізія `candidate` без трафіку → перевірки → трафік.
- **База за інтерфейсом:** сервіс працює з даними через репозиторії (`GroupRepository`, `SubmissionRepository`…), не напряму з Firestore SDK. Переїзд на PostgreSQL = нова реалізація репозиторіїв + перенесення даних; API для клієнта не змінюється.
- **Правила Firestore і Storage — «заборонено все»** для клієнтів; доступ лише в сервісу через Admin SDK.
- **Фонові роботи** — Cloud Scheduler викликає внутрішній ендпоінт сервісу (як нічний перерахунок у duval_backend). Обробка ідемпотентна.

### 5.2 Живі оновлення (WebSocket)
- Події: рейтинг, стрічка, лайки й коментарі, розкриття фото, режим зборів.
- Клієнт підключається з токеном сесії і підписується на свою групу; сервіс шле подію після кожної зміни. Cloud Run тримає з'єднання до 60 хв — клієнт перепідключається сам і дочитує пропущене через REST.
- **Перший сезон — один екземпляр сервісу** (`max-instances=1`, `min-instances=1`): десятки груп він витримає, і немає холодного старту (пропозиція хабу). Розсилка між кількома екземплярами (Pub/Sub або Redis) — коли знадобиться; бібліотека з першого дня має для цього місце (5.3).

### 5.3 Спільні бібліотеки WebSocket (рішення власника 20.11)
Дві мови — дві бібліотеки, обидві використовують усі проєкти, де потрібен WebSocket:

| Бібліотека | Що в ній | Пропозиція хабу щодо місця |
|---|---|---|
| **Клієнт (Dart)** | Підключення з токеном, автоматичне перепідключення з паузами, підписки на теми, дочитування пропущеного після перепідключення, повідомлення стану в `NetworkMonitor` | **Модуль `realtime` у ks_core** — там уже живе стан мережі, з яким клієнт має бути пов'язаний |
| **Сервер (TypeScript, NestJS)** | Шлюз, перевірка токена при підключенні, кімнати/теми, розсилка подій, адаптер розсилки між екземплярами (зараз — в межах одного процесу, далі — Pub/Sub або Redis) | **Нова спільна бібліотека для бекендів** (перша серверна; назва — питання 15.8), підключення через git-тег, як ks_core |

- Основа — робочий WebSocket medvibe і medvibe_backend (own → own), узагальнений і покритий тестами.
- За правилом власника 18.11: щойно бібліотеки з'являться — задачі на перехід для **medvibe** і **medvibe_backend**; власного коду WebSocket там не лишається.
- Бібліотеки — окремі задачі, з тестами всіх залежних проєктів перед злиттям.
- Пропозиція хабу на потім: серверна бібліотека — місце й для інших модулів, які зараз копіюються між бекендами (мінімальна збірка з сервісу оновлень, App Check, вебхук RevenueCat).

### 5.4 Публічна сторінка на karavanstudio.dev (задача sitelanding)
- Статичний HTML у стилі сайту, UA і EN: що це за гра, як працює, для кого (команди, друзі, сім'я), сезонний акцент на Новий рік, кнопки «Створити гру» / «Увійти» → Flutter Web.
- SEO: заголовки, опис, розмітка, sitemap; Open Graph — щоб посилання гарно виглядало в Telegram, Viber, LinkedIn.
- **Посилання-запрошення ведуть на легку HTML-сторінку** («Вас запросили в гру "<назва>"» з прев'ю), яка одразу передає токен у Flutter Web: прев'ю в месенджері показує назву гри, і людина не бачить білого екрана, поки вантажиться Flutter.
- Адреса Flutter Web: `commandvibe.karavanstudio.dev` (рішення власника 26.11).

### 5.5 Що беремо з наявних проєктів (own → own)
- medvibe / medvibe_backend: запрошення за посиланням, групи, WebSocket (через нові бібліотеки, 5.3);
- duval_backend: секрети, порядок деплою, виклики від Scheduler;
- sitelanding: листи через Resend, політики на karavanstudio.dev;
- ks_core: телеметрія й стан мережі — **якщо модулі працюють у вебі** (перевірити першим днем; якщо ні — зміни бібліотеки окремою задачею).

## 6. Вхід і ролі

### Сесії (пропозиція хабу — наслідок «усе через сервер»)
Сервіс сам видає й перевіряє сесії: короткий токен доступу + довгий токен оновлення (у базі — лише хеш). Той самий токен — для REST і WebSocket. Відкликання діє одразу.

### Організатор
- Реєструється через Firebase Auth: **Google** або **посилання на email** (без пароля); сервіс перевіряє вхід Firebase і видає свою сесію. Apple — разом зі сторами.
- Один акаунт — багато груп.
- **Грати не обов'язково** (рішення власника 20.11). Пропозиція хабу, як це влаштувати:
  - при створенні групи перемикач **«Я теж граю»**; увімкнено → організатор стає ще й учасником цієї групи (той самий акаунт, PIN не потрібен), вимкнено → лише керує;
  - можна змінити пізніше: приєднатись посеред гри (як новий учасник — минулі завдання доступні як пізні) або вийти з гри, лишившись організатором;
  - **що бачить організатор, який не грає:** панель керування (учасники, запрошення, налаштування, скарги, HR-звіт), рейтинг і стрічку — але фото **за тими самими правилами, що й учасник, який не виконав завдання**: розмиті до розкриття через 2 дні. Виняток — фото, на яке є скарга: його він бачить одразу, щоб розглянути. Причина: HR, який бачить усе одразу, не граючи, — це вже крок до «стеження» (анти-ціль). Погоджено власником 20.11; «Я теж граю» увімкнено за замовчуванням.

### Учасник — без реєстрації
Організатор обирає для групи **спосіб приєднання** (погоджено власником 20.11: одне посилання — основний спосіб):

| | **А. Одне посилання на групу** (за замовчуванням) | **Б. Список імен** |
|---|---|---|
| Як | Організатор кидає одне посилання або QR у чат. Учасник відкриває, сам вводить ім'я чи нікнейм — і в грі | Організатор вписує імена → кожному персональне посилання і QR |
| Кому | Друзі, сім'я, команди; Telegram Mini App | Коли склад має бути точним (відділ, клас) |
| Організатору | Нічого не вписувати | Вписати й розіслати |
| Захист | Перемикач **«Підтверджувати нових»** (увімкнено за замовчуванням): новий бачить «Чекаємо підтвердження організатора», фото групи йому недоступні, доки не підтвердять. Ліміт кількості учасників. Посилання можна закрити або перевипустити | Посилання одноразове |

Спільне для обох способів:
1. Перше відкриття — через HTML-сторінку запрошення (5.4); сервіс видає сесію.
2. Ім'я унікальне в групі; учасник може змінити його пізніше, організатор — виправити. Для HR-звітів — необов'язковий вибір відділу зі списку, який задав організатор.
3. Одразу пропонуємо 4-значний PIN. Вхід з іншого пристрою: посилання групи → «Я вже в грі» → своє ім'я → PIN (щоб та сама людина не з'явилась двічі).
4. Організатор може вилучити учасника: сесії відкликаються, живі події припиняються одразу; і перевипустити вхід тому, хто загубив PIN.
5. Вхід через Telegram Mini App без PIN (розділ 8) — працює зі способом А.

**Технічно:** токени запрошень і посилання групи — 128 біт, у базі лише SHA-256; PIN — argon2, 5 помилок → блок на 15 хв, скидає організатор.

### Великий екран
Той самий екран «Сьогодні» (розділ 6а) у режимі показу: окреме посилання лише для читання, без входу учасника — для телевізора чи проєктора на зборах.

## 6а. Екрани застосунку (пропозиція хабу за побажаннями власника 20.11)

Мобільний вигляд — основний. П'ять вкладок унизу:

| Вкладка | Що там |
|---|---|
| **Сьогодні** | Спільний головний екран, який бачать усі при вході (колишній «екран зборів») |
| **Календар** | Усі завдання гри: сітка «дверцят» |
| **Стрічка** | Виконані завдання з фото й коментарями, як в Instagram |
| **Рейтинг** | Дошка рейтингу наживо (розділ 9) |
| **Я** / **Група** | Аватар, мої бали з журналом, прихильники, джокери, PIN, «видалити мої дані»; для організатора — керування групою |

### Сьогодні
Згори донизу:
1. **Завдання дня** — картка з назвою, описом, часом до кінця дня і кнопкою «Виконати» (або «Виконано ✓ +12 балів»).
2. **Рулетка** — з'являється, якщо режим групи потребує вибору, а сьогодні ще не крутили: «Сьогодні обирає Олена — лишилось 2 год». Коли рулетку запускають, **усі, хто в застосунку, бачать ту саму анімацію одночасно** (WebSocket: сервер шле результат і час старту). Хто зайшов пізніше — бачить короткий повтор і результат. Не обрали вчасно — обирає гра.
3. **Хід дня** — «7 з 12 уже виконали», спільна ціль 80%.
4. **Карусель сьогоднішніх фото** — горизонтальний ряд (розмиті з написом для тих, хто ще не виконав). Дотик відкриває перегляд на весь екран.
5. **Моє місце** — «ти 4-й, до 3-го — 6 балів» і три лідери.
6. **Події** — «Олена вийшла на 1-ше місце», «фото за 1 грудня відкрились».

### Календар — доступ до завдань
- Сітка днів гри. Майбутні дні — зачинені дверцята. Відкриті — з позначкою: виконано / ще можна виконати / розкрито.
- Дотик до дня: завдання, моє фото або кнопка «Виконати» (пізнє виконання — до кінця челенджу, із зазначенням, скільки балів дасть), і всі фото цього дня.
- Тут учасник наздоганяє пропущене — одне місце, де видно все, що він ще може зробити.

### Стрічка — як Instagram
- Вертикальна стрічка виконань, новіші згори: фото, автор, завдання, лайк, кількість лайків, коментарі під фото.
- Фото, яке ще не відкрилось для мене, — розмите з написом (розділ 7) і без коментарів; лайкати й коментувати можна лише відкриті.
- Дотик до фото — **перегляд на весь екран із гортанням** убік між фото цього дня (як сторіз), коментарі знизу.
- Фільтри: за днем, за учасником, «мої».
- Коментарі — простий список без гілок; автор може видалити свій, організатор — будь-який; «Поскаржитись» на фото й коментар.
- Нові фото, лайки й коментарі з'являються наживо.

### Хто що бачить про дії інших (лайки — рішення власника 20.11; решта — пропозиція хабу)
| Дія | Хто бачить |
|---|---|
| **Лайк = голос за фото** | Окремого голосування за фото немає: лайки і є голосами («глядацькі симпатії», найпопулярніше фото, приз у фіналі). За замовчуванням імена тих, хто лайкнув, бачать усі, кому фото відкрите. Організатор може ввімкнути **«Показувати лише кількість лайків»** — тоді імен не бачить ніхто, і автор теж; «прихильники» показуються числом |
| **Перегляд** («хто подивився») — **після сезону, не пріоритет** (рішення власника 20.11) | Лише автор фото: «Переглянули 8 з 12» і список імен, як у сторіз. Рахується відкриття фото на весь екран. Організатор списків переглядів не бачить; у HR-звіті — лише загальні числа |
| **Коментар** | З іменем, усі, кому фото відкрите |
| **Вибір завдання групою** (режим 4 — це не лайки) | Анонімно, видно лише підсумок |
| **«Штурхнути»** | Анонімно |
| **Скарга** | Автор не бачить, хто поскаржився; бачить організатор |

Причина поділу: лайки й перегляди з іменами гріють гру (автор бачить, що його фото дивляться), а все, де можливий тиск чи образа, — анонімне. Перегляди бачить лише автор, бо список «хто не дивився» в руках організатора — це вже стеження.

## 7. Фото і розмиття

Це серце гри й головний ризик приватності.

1. Клієнт зменшує фото (довга сторона до 1600 px) і надсилає **сервісу**.
2. Сервіс: читає час зйомки з EXIF → **видаляє EXIF** (перекодування) → зберігає оригінал і **розмите прев'ю** (сильне розмиття зі зменшеної копії 32 px — відновити зображення неможливо) → створює виконання і нараховує бали. Одним кроком.
3. **Коли відкривається оригінал** — за **будь-якої** з умов:
   - учасник має власне виконання цього завдання;
   - минуло 2 дні від відкриття завдання, **о 9:00** за часом групи (рішення власника 20.11). Приклад: завдання 1-го числа → 3-го о 9:00 його фото бачать усі.
4. Лайки й коментарі — ті самі умови: обговорення відкривається разом із фото.
5. **Напис на розмитому фото** (рішення власника 20.11), щоб розкриття не було несподіванкою:
   - «Виконай завдання — і побач одразу» з кнопкою «Виконати»;
   - «або відкриється 9 грудня о 9:00» — конкретна дата й час за часом групи;
   - після розкриття для тих, хто ще не виконав: «Ще можна виконати — до кінця челенджу».
   Напис накладається в застосунку поверх прев'ю, тексти UA і EN. Пропозиція хабу: те саме пояснення один раз у знайомстві з грою і в правилах групи.
6. Сервіс видає оригінал лише як **коротке підписане посилання** (кілька хвилин) після перевірки умов. Розмиття в застосунку — лише вигляд, захист на сервері.
7. Розкриття — фонова робота о годині розкриття: позначає клітинку «розкрито» і шле подію через WebSocket.
8. Сховище: `groups/{groupId}/cells/{cellId}/{memberId}/original.jpg` і `…/blur.jpg`.

**Анти-чит у вебі слабший**, ніж у SPEC, — власник прийняв це 20.11 (веб буде основним способом гри, особливо для тих, хто не любить встановлювати застосунки): браузер не може заборонити вибір з галереї. У першому сезоні: позначка «знято раніше, ніж відкрито завдання» (за EXIF) + скарги учасників → організатор відхиляє фото. «Лише з камери» — у мобільних застосунках пізніше.

## 8. Сповіщення і Telegram

Три канали, від обов'язкового до додаткового:

| Канал | Коли працює | Хвиля |
|---|---|---|
| **У застосунку** — дзвіночок і спливні повідомлення | Завжди. Поки застосунок відкритий — наживо через WebSocket; коли закритий — чекає в списку до наступного входу | 1 |
| **Telegram-бот** — чат групи й особисті повідомлення | Коли застосунок закритий; основний спосіб «покликати» людину | 1 — чат групи; 2 — особисті |
| **Веб-push** | Android і комп'ютер — якщо дозволено в браузері, приходить і при закритій вкладці. iPhone — лише якщо гру додано на головний екран | 1 (рішення власника 20.11: разом із ботом) |

**Якщо застосунок відкритий, push не потрібен:** подію вже приніс WebSocket, показуємо її всередині застосунку. Системне сповіщення надсилаємо, лише коли людина не в застосунку, — без дублів.

### Де це в інтерфейсі
- **Дзвіночок** у верхній панелі на всіх вкладках, із лічильником непрочитаних. Відкриває список «Сповіщення»: згруповано за днями, дотик веде до фото, завдання чи рейтингу. Список зберігається на сервері — однаковий на всіх пристроях.
- **Спливне повідомлення** внизу екрана на кілька секунд, коли щось сталося наживо («Олена вийшла на 1-ше місце»).
- **Позначки на вкладках:** крапка на «Стрічці» (нові фото), на «Сьогодні» (нове завдання, твоя черга крутити рулетку).
- **Налаштування у вкладці «Я»:** вимкнути окремо «завдання», «лайки й коментарі», «рейтинг»; канали (Telegram, push). Тихі години — 22:00–8:00 за часом групи, без сповіщень поза застосунком.

### Які сповіщення (погоджено власником 20.11)
| Подія | Кому | У застосунку | Telegram | Push |
|---|---|---|---|---|
| Відкрилось завдання дня | усім | ✅ | чат групи | ✅ |
| Твоя черга обирати (рулетка) | обраному | ✅ | особисто | ✅ |
| Нагадування ввечері: «7 з 12 уже виконали» | тим, хто не виконав | ✅ | особисто | ✅ |
| Фото дня відкрились (9:00, через 2 дні) | усім | ✅ | чат групи | — |
| Лайки на твоє фото | автору | ✅, зведено: «5 людей вподобали» | — | — |
| Коментар до твого фото | автору | ✅ | — | ✅ |
| Тебе «штурхнули» | адресату | ✅ | особисто | ✅ |
| Тебе обігнали / ти в трійці | учаснику | ✅ | — | — |
| Спільна ціль 80% досягнута | усім | ✅ | чат групи | — |
| Новий джокер, бейдж | учаснику | ✅ | — | — |
| Підсумки гри, колаж | усім | ✅ | чат групи | ✅ |
| Організатору: новий учасник чекає підтвердження, скарга | організатору | ✅ | особисто | ✅ |
| Організатору: дані видаляться через 7 днів / 1 день | організатору | ✅ | особисто | + лист |

Правила: поза застосунком — не більше 3 сповіщень на людину на день (крім особистих: черга, штурхання, скарга); ніхто, крім самого учасника, не отримує сповіщень про те, що він чогось **не** зробив.

### Telegram-бот
- **Чат групи:** організатор додає бота в чат → бот пише за таблицею вище.
- **Особисто:** учасник натискає «Нагадувати в Telegram» → бот з його токеном.
- Viber-групи: бота в першому сезоні немає; організатор копіює готовий текст дня кнопкою «Поділитись».
- Webhook для Slack/Teams (SPEC §10) — після сезону.

### Telegram Mini App (вхід — хвиля 1, оформлення — хвиля 2; погоджено 20.11)
Власник 20.11: «якщо бот однаково буде — може, одразу і Mini App, якщо це недовго?». Оцінка хабу: **вхід через Mini App — ~1 день** (перевірка підпису Telegram на сервері + відкриття застосунку з кодом групи); оформлення під Telegram (тема, кнопка «назад», розмір екрана) — ще ~1 день. Пропозиція: **вхід — у хвилі 1, оформлення — у хвилі 2**; якщо хвиля 1 не встигає, Mini App відкладаємо першим. Аргумент «за»: перші групи — українські й, найімовірніше, у Telegram; одне посилання в чат замість персональних посилань і PIN — головне для «увійти за 10 секунд».

Той самий Flutter Web, відкритий **всередині Telegram** кнопкою бота або посиланням `t.me/<бот>/<app>?startapp=<код>`. Окремого застосунку немає.
- **Вхід без PIN і без персональних посилань:** Telegram передає підписані дані користувача, сервіс перевіряє підпис ключем бота і видає ту саму сесію (розділ 6).
- **Одне посилання на групу:** організатор кидає його в чат, кожен обирає своє ім'я — і в грі.
- **Особисті нагадування:** застосунок одним запитом просить дозвіл боту писати користувачу.
- Звичайний вебвхід лишається для Viber-груп, західних компаній і тих, у кого Telegram обмежений на роботі.
- Перевірити: швидкість першого завантаження Flutter і камеру у вбудованому браузері Telegram (iPhone, Android).
- Оплата пізніше: для цифрових товарів у Mini App — Telegram Stars (умови перевірити перед оплатою).

## 9. Ігрові механіки

### Календар
Гра — сітка клітинок-«дверцят» (як адвент-календар). **Початок і тривалість довільні** (7–31 день): група, що приєдналась 5 грудня, грає свій повний цикл.

### Режими вибору завдання
На сервісі — стратегії (`TaskPicker`), режим — налаштування групи.

| # | Режим | Суть |
|---|---|---|
| 1 | Авто щодня | Завдання відкривається у заданий час |
| 2 | Рулетка учасника | Випадковий учасник обирає клітинку; не обрав за 3 год → обирає гра |
| 3 | Режим зборів | Великий екран: рулетка обирає учасника, він відкриває клітинку; анімація в усіх одночасно |
| 4 | Голосування | 3 закриті картки (видно категорію), група голосує до 10:00 |
| 5 | Естафета | Обирає той, хто першим виконав учорашнє |
| 6 | Шанс відігратися | Обирає останній у рейтингу |
| 7 | Раптова клітинка | Відкривається у випадковий момент; перші 2 год — подвійні бали |
| 8 | Парне завдання | Рулетка поєднує двох, виконують разом |

Рулетка з вагами: хто давно не обирав — більший шанс; кожен гарантовано отримує чергу. Синхронна анімація: сервіс записує результат і час старту й розсилає через WebSocket; клієнти програють ту саму анімацію від цього часу.

### Бали (погоджено власником 20.11)
Балів за поставлені лайки немає (20.11): лайк — це голос, а платити за голосування означає знецінити його.
| Подія | Бали |
|---|---|
| Виконання в день завдання | 10 |
| Швидкість: 1-й / 2-й / 3-й | +5 / +3 / +2 |
| Пізнє виконання (до кінця челенджу) | −2 за кожен день запізнення, не менше 4 |
| Глядацькі симпатії (лайки на фото) | до +5 за фото, залежно від частки групи, що лайкнула (нижче) |
| Спільна ціль: 80% групи виконали | +3 кожному, хто виконав |
| Раптова клітинка, джокер «подвоєння» | ×2 до бази |
| Фінал: «Приз глядацьких симпатій» | +15 тому, в кого найбільше прихильників |

**Глядацькі симпатії** (побажання власника 20.11: лайки — основа, щоб у учасників були прихильники). Пропозиція хабу — бали **від частки групи**, а не від числа лайків, щоб правило однаково працювало в групі з 5 і з 40 людей:
- бали за фото = `5 × лайки / (учасників − 1)`, округлено вниз, не більше 5. Лайкнули всі — 5 балів; половина групи — 2 бали;
- приклад: група з 11 → кожні 2 лайки ≈ +1; група з 41 → кожні 8 лайків ≈ +1;
- свої фото лайкати не можна; лайк можна зняти — бали перераховуються.
- **Прихильники:** скільки різних людей лайкнули хоч одне твоє фото. Видно в профілі учасника і в рейтингу; найбільше прихильників наприкінці → «Приз глядацьких симпатій».

**Журнал балів:** кожне нарахування — окремий запис (хто, за що, скільки). Рейтинг = сума журналу. Учасник бачить, звідки його бали; правила можна змінити й перерахувати.

### Дошка рейтингу наживо (побажання власника 20.11)
Щоб дух змагання тримався весь місяць:
- окрема вкладка «Рейтинг» і компактний блок «ти на 4-му місці, до 3-го — 6 балів» на головному екрані;
- оновлюється **наживо через WebSocket**: щойно хтось виконав завдання чи отримав лайк — рядки міняються місцями з анімацією, біля учасника — стрілка «↑2»;
- події дня в стрічці: «Олена вийшла на 1-ше місце», «Андрій отримав 10 лайків за ялинку»;
- на екрані зборів — великий рейтинг для всіх;
- рейтинг показує лише бали й місце; хто що не виконав — не показує (анти-ціль «стеження»).

### Щоб не відсиджувались
Спільна ціль 80%, «7 з 12 уже виконали», анонімне «штурхнути» (не більше 1 на людину на день), розмиті прев'ю з написом, пізнє виконання зі зменшенням балів, джокери за серії (пропуск / подвоєння / передай іншому). Організатор бачить, хто давно не активний, — **лише він і лише в цій групі**.

### Фінал
Топ-3 і номінації («найшвидший», «найпопулярніше фото», «приз глядацьких симпатій»), колаж-сітка з водяним знаком (сервіс збирає з фото; відео — пізніше), HR-звіт організатору.

**Призи** (рішення власника 20.11): організатор вписує назви призів — за 1, 2, 3 місце і за номінації (текст і, за бажанням, емодзі). Перемикач **«Показувати призи одразу»**: увімкнено — учасники знають, за що змагаються (призи видно на вкладці «Рейтинг»); вимкнено — призи відкриваються у фіналі як сюрприз. Гра лише показує призи: грошей не приймає і не видає.

### Тайний Санта
Рішення власника 20.11: Санта — **необов'язкова частина групи**, і може жити **окремо від гри**.
- При створенні групи організатор обирає: «Челендж», «Тайний Санта» або обидва. Санту можна додати й пізніше.
- Участь у Санті кожен підтверджує сам (не всі хочуть дарувати): до дати жеребкування учасник натискає «Беру участь» і заповнює вішлист.
- Організатор задає дату жеребкування, орієнтовний бюджет і дату обміну.
- Жеребкування серед тих, хто підтвердив (ніхто не дарує собі; потрібно щонайменше 3 учасники). Призначення бачить лише дарувальник.
- Група «лише Санта» — безкоштовний вхід: з неї одним перемикачем запускається челендж.

### База завдань
~100 новорічних завдань (AI + ручна вичитка власника), теги з SPEC §6, **українська й англійська з першого дня**.

**Як організатор складає календар** (рішення власника 20.11):
- **Автоматично:** обирає теми → гра підбирає завдання на всі дні, без повторів.
- **Вручну:** обирає завдання з бази сам (пошук і фільтр за тегами).
- **Змішано:** підібране автоматично можна **замінити** — кнопка «Інше» на будь-якому дні дає наступне завдання з тих самих тем, якого в цій грі ще немає; дні можна переставити; можна вписати власне завдання.
- Міняти можна лише дні, які ще не відкрились. Учасники майбутніх завдань не бачать.

### Аватари (рішення власника 20.11)
- Стандартний — кружечок з ініціалами.
- **Колекція аватарів** на вибір (перший набір — новорічні персонажі, ~24 шт., власні ілюстрації без чужих прав). Хвиля 1.
- Власне фото як аватар — хвиля 2 (пропозиція хабу: це ще одне місце для недоречних фото і скарг; колекції для старту досить).

## 10. HR-звіти

Агреговані, **не інструмент стеження** (SPEC §11): без «Іванов не виконав 12 завдань»; розбивка за відділами — лише якщо у відділі ≥ 5 людей.
- **Перший сезон (MVP зі SPEC):** залучення (приєдналось із запрошених, %), активність по днях, рейтинг завдань (популярні й пропущені).
- Формат: сторінка-звіт у застосунку + PDF і CSV.
- Далі: зв'язки між командами, активний час доби, фінальне опитування.

## 11. Життєвий цикл даних

```
active → finished → retention (30 днів) → hard delete
```
- Щоденна робота: видаляє Storage за префіксом групи і документи Firestore рекурсивно; пише, що видалено.
- Нагадування за 7 днів і за 1 день: банер, Telegram, лист організатору (Resend).
- Перед видаленням безкоштовно: колаж, ZIP усіх фото й HR-звіт (сервіс збирає на запит).
- Учасник: «Видалити мої дані» → фото, коментарі, лайки; у рейтингу «Учасник видалений».
- Організатор: видалити групу → 24 год на скасування → остаточно.
- Платне продовження архіву — після сезону, разом з оплатою.

## 12. Модель даних (Firestore, за репозиторіями сервісу)

```
organizers/{uid}                      email, createdAt
sessions/{sessionId}                  subject (organizer|member), refreshTokenHash, deviceInfo,
                                      revokedAt?, createdAt
groups/{groupId}                      ownerUid, name, mode, status, startsAt, days, openTime,

  members/{memberId}                  displayName, avatar, department?, santaOptIn?, lastActiveAt, deletedAt?
    private/secrets                   inviteTokenHash, pinHash?, pinFailures, telegramUserId?, telegramChatId?
  cells/{cellId}                      dayIndex, taskId?, taskSnapshot, opensAt, openedAt?, revealAt,
                                      revealed, pickedBy?, pickMode, multiplier
    submissions/{memberId}            photoPath, blurPath, takenAt?, uploadedAt, flags, status

      comments/{commentId}            memberId, text, createdAt
```

- `submissions/{memberId}` — id = id учасника: одне виконання на завдання.
