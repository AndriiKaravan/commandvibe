# CommandVibe — Project Overview

**Дата оновлення:** 2026-11-26
**Версія документа:** 1.0 (перший огляд за дизайном; коду ще немає)

> **Статус: план.** Дизайн на вичитці власником (розділи 6–17), код не написано. Деталі — у `docs/specs/2026-11-19-photo-challenge-design.md`.

## Загальна інформація

- Групова фото-челендж гра: організатор запускає гру на 7–31 день, щодня відкривається завдання, учасники виконують його фото. Чужі фото розмиті, доки учасник не виконав завдання сам або не минуло 2 дні (о 9:00 за часом групи).
- Бали, лайки як голоси, рейтинг наживо, фінал (топ-3, номінації, колаж), HR-звіти, необов'язковий Тайний Санта.
- Назва: CommandVibe (рішення власника 26.11). Веб: `commandvibe.karavanstudio.dev` (окремий сайт Firebase Hosting). Публічна сторінка — на `karavanstudio.dev`. Бот Telegram: `@CommandVibeBot` (перевірити).
- Запуск перших груп: орієнтовно 8–12 грудня 2026.
- Мови: UA і EN. Анти-цілі: стеження за людьми, витік фото, ручна щоденна робота організатора.

## Модулі

- **Клієнт** — Flutter Web (PWA): вкладки «Сьогодні», «Календар», «Стрічка», «Рейтинг», «Я/Група»; великий екран (режим показу).
- **Сервіс** — Node.js + TypeScript (NestJS), Cloud Run: уся ігрова логіка, доступ до фото, сесії.
- **Фонові роботи** — Cloud Scheduler кожні 5 хв: відкриття завдань, розкриття фото, нагадування, видалення; ідемпотентні.
- **Сповіщення** — у застосунку, Telegram-бот, веб-push.
- **Telegram Mini App** — вхід (хвиля 1), оформлення (хвиля 2).
- **Публічна сторінка й сторінка запрошення** — статичний HTML на karavanstudio.dev (задача sitelanding).
- **Спільні бібліотеки (змінювати звідси заборонено):** `ks_core` (клієнт, модуль `realtime`), `ks_server` (сервер, WebSocket-шлюз).

## Архітектура

- Клієнт працює лише з сервісом: REST для дій і читання, WebSocket для живих оновлень. До Firestore і Storage клієнт доступу не має (правила «заборонено все»).
- Сервіс працює з даними через репозиторії (`GroupRepository`, `SubmissionRepository`…), щоб міграція на PostgreSQL не торкалась API.
- Окремий Firebase-проєкт, регіон ЄС (Firestore/Storage — `europe-west`, Cloud Run — `europe-central2`).
- Перший сезон — один екземпляр сервісу (`max-instances=1`, `min-instances=1`); клієнт перепідключається сам і дочитує пропущене через REST.
- Фото: клієнт зменшує до 1600 px → сервіс видаляє EXIF, зберігає оригінал і розмите прев'ю, видає оригінал лише коротким підписаним посиланням після перевірки умов.
- Клієнт: go_router, ChangeNotifier/MVVM, шар репозиторіїв.
- Деплой бекенду: ревізія `candidate` без трафіку → перевірки → трафік. Секрети — Secret Manager.
- Життєвий цикл групи: `active → finished → retention (30 днів) → hard delete`.

## API

План; контракт ще не спроєктовано.
- **Сесії:** сервіс видає короткий токен доступу + токен оновлення (у базі хеш); один токен для REST і WebSocket.
- **Організатор:** вхід через Firebase Auth (Google або email-посилання) → сесія сервісу.
- **Учасник:** без реєстрації — посилання на групу (або список імен), ім'я, PIN (argon2, 5 помилок → блок на 15 хв); токени запрошень — 128 біт, у базі SHA-256.
- **WebSocket-події:** рейтинг, стрічка, лайки й коментарі, розкриття фото, рулетка.
- **Внутрішній ендпоінт** для Cloud Scheduler.
- **Telegram:** webhook бота; перевірка підпису Mini App.

## Моделі даних

Firestore (за репозиторіями сервісу), повна схема — розділ 12 дизайну:
`organizers`, `sessions`, `groups` (`members` + `private/secrets`, `cells` → `submissions` → `likes`/`comments`, `points`, `standings`, `nudges`, `jokers`, `santa`), `tasks` (UA+EN), `inviteIndex`.
Сховище фото: `groups/{groupId}/cells/{cellId}/{memberId}/original.jpg` і `blur.jpg`.
Бали — журнал `points`; рейтинг = сума журналу.
